## 1. 验收原则

区分四种结论：`Pass`、`Fail`、`NotRun`、`Deferred`。代码已存在、脚本成功启动、主界面能打开、设计图已确认，都不自动等于功能或体验 Pass。

本轮分别核验功能正确性、交互性能、真实视觉和数据安全。已有用例继续使用；新增指标不能只改文档阈值而没有采样实现，也不能以提高看门狗超时来解决卡顿。所有指标是未来退出门槛，**不是当前实测结果**。

## 3. 交互指标与测量口径

### 3.1 采样点

使用同一单调时钟记录：输入接收、意图更新、解码开始/结束、合成提交、Present、可关联到该输入的画面出现。记录 request/generation、工程修订、请求 Project Tick、实际 Source PTS，防止把旧画面 Present 算作新位置响应。

Present 返回不天然等于用户已经看见；软件测量记录其边界，最终用帧编号动画和窗口视频复核可见反馈。无需把整个桌面作为诊断素材；采集前说明范围，仅采集测试窗口。

输入处理耗时只证明消息循环响应，不能用它代替输入到画面耗时。静止画面不适合测连续预览更新率；该指标使用 F03 唯一可识别帧。被合并的指针请求不要求逐个显示，但不能漏掉最终位置。

|---|---|---|

| RE-PERF-04 | 单击定位 / 松手到精确帧 | P95 ≤250 ms、最大 ≤750 ms；实际 PTS 与索引选择一致 |
| RE-PERF-05 | 定位后空格到连续播放首帧 | 输入意图 ≤50 ms；实际首帧 P95 ≤250 ms、最大 ≤750 ms；再次空格立即取消 |
| RE-PERF-06 | 镜头/视频边缘拖动与松手 | 草稿反馈满足 RE-PERF-01/02；松手 UI 提交 P95 ≤50 ms，后续画面满足 RE-PERF-04；一次 Undo |
| RE-PERF-07 | 稳定播放 | 1440p60 源在固定验收机连续播放 60 秒：视频 Present 间隔 P95 ≤25 ms、P99 ≤50 ms、最大 ≤100 ms；无黑帧/闪烁；内容时间正常前进 |
| RE-PERF-08 | 暂停与资源边界 | 无交互暂停 5 秒不重解码/重合成；合成输出 Readback 为 0（显式兼容路径单列）；任务/缓存不随输入或时长无限增长 |

RE-PERF-03 中“相应”指当前拖动方向与附近位置的近似预览，除了请求响应时间，还须报告 `previewTimeErrorTick`（实际画面相对被服务目标的差）；时间误差 P95 ≤150 ms、最大 ≤300 ms。跨大距离快速跳转可合并中间请求，但不能拿很旧的关键帧反复 Present 达到更新率。松手始终收敛到精确源帧。

每个 F01～F05 执行三轮前进、后退、方向反转与首尾跳转；每轮连续拖动 10 秒。离散定位/松手/播放样本每类累计不少于 100，报告 P50/P95/P99/最大值和失败数；按素材和冷/热态分别报告，不混合后掩盖 F02。F03 验证更新率，F04/F05 验证相同延迟预算与连续响应。不得只跑 5 秒新录制工程就宣布长工程通过。

R1 为帧缓存制定并记录固定字节预算，热身后连续 5 分钟往返拖动验证淘汰与在途任务上限；不能每个鼠标事件排一个无法取消的完整解码任务。GPU/驱动异常的退出单列故障测试，不能混作正常输入性能。

## 6. 阶段放行与问题等级

- R0：设计原型获确认、素材和指标采样方案固定；不能标 UI Pass。
- R1：已有镜头编辑/预览路径的 RE-PERF、RE-SEEK、RE-LIFE 核心通过；R3 新增视频片段后补测对应拖动与映射路径。有条件延期必须列出具体场景，不能无条件进入发布。
- R2：RE-UI 全部通过且性能无回退；后续新增控件继续复验。
- R3/R4：新增功能、安全和导出对应项全部通过。
- R5：所有必测项和最终构建复验通过，才能标记 RE-MVP 完成。

阻断项包括：崩溃/数据损坏、正常源无法定位、持续拖动不更新、输入无响应、闪烁、不可达操作、明显文字遮挡、基础剪辑/导出缺失。不能以“不是算法问题”降级。片段恒定变速已由用户加入本轮；T1、音频、速度曲线及自动自然度专项按范围为 Deferred，不将其当成通过，也不阻塞本轮。

# 录制器与编辑器 UI / UX 审计及改进方案

日期：2026-09-19  
范围：当前 Rust / Win32 源码、现有设计规范、历史原型截图、拖动预览与光标合成链路。  
状态：审计与方案；本次未修改应用代码、未生成新版 EXE，也未将历史验收状态改为通过。

## 结论

当前问题涉及信息层级、控件实现、交互反馈和预览画质四个层面。处理顺序确定为：先修复拖动清晰度与交互一致性，再统一组件和布局，最后以真实原生窗口完成视觉验收。保留现有录制、剪辑、撤销、保存及 GPU 预览内核。

设计方向：克制、清晰的桌面创作工具。浅色工具区、深色预览舞台；蓝色集中用于主要动作和选中状态，紫色仅区分镜头轨道。录制器围绕“选择来源—开始录制”，编辑器围绕“预览—剪辑—调整—导出”。删除常驻内部说明，用实际状态替代。

本次无法完成实际窗口观察：computer-use 初始化后，`sky.list_apps()` 返回 `failed to launch codex app-server: program not found`。已查看的 9 月 5 日图片是 HTML 原型截图，不是当前 EXE 截图。因此，下表明确区分代码事实、设计判断和待实机确认项；不能据此宣称已经复现并修复用户机器上的全部现象。

### “移动时间线变糊”的边界

已确认拖播放头存在明显降采样机制，是与反馈高度吻合的首要原因，但本次没有实机拖动证据。必须分别检查三类操作：

1. **拖播放头、在标尺定位**：走 `begin_timeline_scrub → ScrubPreviewWorker → prepare_external_scrub_frame`，会呈现上述低分辨率帧。
2. **滚动或横向平移时间线**：源码主要改变 `TimelineViewport` 并重绘时间线，不主动换媒体清晰度。如果该操作也使画面或整个窗口变糊，需要独立检查重绘、DPI和预览表面缩放，不能直接归因于代理。
3. **上下拖时间线分隔条**：会改变预览尺寸并重新呈现，需要另查窗口尺寸、交换链尺寸及图像采样是否匹配。

当前松手流程已经调用 `seek_absolute`，再经无尺寸限制的原素材解码 worker恢复精确帧（`preview.rs:277`、`preview_window.rs:2293–2310/2678`）。方案是在现有机制上改进拖动质量、刷新与过期结果过滤，不重复建设一个“松手恢复原图”的功能。代理只用于交互预览，不能据此断言导出也变糊。

### 属性栏布局的具体复核

按当前默认时间线高度、足够宽的客户区和展开状态代入布局公式：客户区高度720 DIP时，属性区可用431 DIP，高于紧凑模式405 DIP门槛，面板显示；高度增加到730 DIP后切换为普通布局，可用423 DIP，低于435 DIP门槛，面板反而消失；760 DIP时才重新显示。这是代码公式推导，不是实际窗口测试，但足以说明不能仅通过微调隐藏阈值解决自适应布局问题。

## 具体设计

### 录制器

- 顶部：Panzo、打开工程、更多。诊断和项目目录放入更多。
- 中央440–480 DIP内容区：简短标题“新录制”；屏幕/窗口分段选择；来源名称、实际分辨率和简洁来源图示；“不录制声音”；开始录制。
- 主要按钮高44–48 DIP，圆形录制图标与文字一起居中。停止状态用方形图标、时长和清晰的“停止录制”，除录制状态外不大面积使用红色。
- 底部次级入口显示“继续编辑”及最近工程名；没有最近工程时隐藏，不保留无意义的禁用大按钮。
- 启动中显示“正在准备录制…”，录制中突出计时和停止；停止后显示“正在完成录制…”，成功直接进入编辑器。启动阶段是否可取消由现有录制状态机能力决定，不提供无效取消按钮。
- 删除常驻口号和“本地优先 / 非破坏性编辑”。保留无声音这一影响录制结果的信息；不添加无能力支持的麦克风开关。

### 编辑器

- 顶栏56–60 DIP：返回、工程名、紧凑保存状态；撤销/重做；右侧保存、更多、导出。导出为唯一蓝色主按钮。
- 中央：深灰预览舞台，保持合理内边距；不要把文件元数据和技术状态叠在素材上。镜头选中时才显示可拖动的焦点控件，焦点编辑覆盖层不进入导出。
- 播放条44–48 DIP：回到开头、播放/暂停、当前时间/总时长；帧前进后退可通过快捷键及紧凑控件提供。右端保留属性栏入口和“适应”视图状态。
- 属性栏264–280 DIP：画布、选中片段或镜头的相关参数，统一字段对齐；高度不足滚动。无选择时展示画布样式；选择片段后明确对象，避免同名字段改变含义。
- 时间线200–240 DIP起始高度，可调整；顶部剪辑工具与缩放分左右两组。视频轨道48–56 DIP、镜头轨道28–32 DIP，播放头和裁剪手柄的热区独立于视觉宽度。
- 取消底部永久参数行和常驻技术状态行，把空间归还预览与轨道。快捷键放在提示中；短暂结果放在靠近动作的位置，错误需有“重试 / 查看详情”等对应操作，详情保留原始诊断。
- 小窗口不缩小所有文字或让控件消失；顶栏次要命令进入更多，属性页仍可达。高DPI按物理工作区检查，不能只用“1440×900 DIP乘缩放”代替真实屏幕。

### 统一控件与指针

控件尺寸以DIP定义：普通按钮32–36，图标按钮32×32，图标16–18，圆角6–8，组内间距8、组间16、面板内边距16–20。正文13–14，说明12；数字采用等宽数字布局。主按钮、普通按钮、工具按钮、分段选择、开关、滑杆、数值输入各有独立角色。

所有可交互组件具有默认、悬停、按下、禁用、键盘焦点；开关的“开启”和命令的“按下”分开。已有命令按下/释放、Esc取消和一次拖动一次撤销逻辑继续复用。滑杆、色块、分段选择也要补齐状态，而不只是通用按钮。

| 位置 / 操作 | 指针和反馈 |
|---|---|
| 常规区域、普通桌面按钮 | 系统箭头；按钮用悬停和按下态反馈 |
| 真正链接 | 手形 |
| 数字输入 | 文本I形；支持选中、粘贴、Enter应用、Esc取消 |
| 视频/镜头两端、播放头拖动 | 水平调整指针；高亮实际命中的手柄 |
| 时间线高度分隔条 | 垂直调整指针 |
| 可移动镜头片段、时间线平移 | 开手 / 握手；按下后明确进入拖动状态 |
| 镜头焦点 | 仅命中焦点控件时显示移动指针，拖动时保持 |
| 不可操作对象 | 默认指针和禁用状态，不显示可点击手形 |

非捕获状态统一处理 `WM_SETCURSOR`；捕获状态根据当前手势主动维护指针；结束、Esc、失焦、捕获丢失均恢复。Windows默认处理可能恢复窗口类指针，不能只依赖 `WM_MOUSEMOVE` 里临时调用 `SetCursor`。[Microsoft消息说明](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-setcursor)

录制成片内的光标与应用操作指针是两件事。第一阶段先修正成片箭头形状、抗锯齿、热点和尺寸稳定性。当前事件结构只记录位置/可见性，无光标形状与热点资产（`panzo-core/src/events.rs:18`）；旧工程无法恢复真实I形/手形光标。若扩展为保留原始系统光标，需另加形状事件、资产去重及版本兼容，不能只改着色器就声称支持。

## 拖动预览清晰度策略

1. **默认清晰优先。** 根据实际预览物理像素、素材尺寸和镜头裁切范围选择解码尺寸；放大镜头也计入需求。比如显示区域宽1000像素、镜头显示源宽一半时，源纹理至少需要约2000像素宽的采样密度，640或960均不足。源本身分辨率不足除外。
2. **按需求选档，不写死640。** 可用1280、1920、源尺寸的有界档位，选满足采样需求的最低档；是否生成对应短GOP缓存取决于源素材随机访问成本和预算。短GOP、缓存命中和后台解码继续作为提速手段。
3. **时间线交互与解码分离。** 播放头立即随指针更新；worker只保留最新待处理意图，使用现有generation、工程修订和源时间映射过滤旧结果。不要为每次鼠标移动创建线程或无限排队。
4. **清晰优先模式下降低更新频率应早于明显降低空间分辨率。** 有效预览仍需达到既有连续更新门槛；不能用长期静止画面冒充流畅。可在预览菜单提供“清晰 / 流畅”作为显式偏好，只有用户选择流畅时才允许明显较低的预览分辨率。
5. **手势内稳定、停住即细化。** 手势开始选定档位，避免来回切换造成清晰度闪变。指针停留约100–150ms即可请求更精细帧，不必等松手；新移动立即取消旧细化意图。松手后继续现有原素材精确定位，精确结果到达后不得被旧代理结果覆盖。
6. **无全局模糊和过渡淡化。** 等待时保留最近有效帧；明显等待时显示轻量“正在更新画面…”，不盖住素材。正常成功状态不显示缓存/代理技术信息。
7. **缓存同步升级。** 新缓存身份至少包含源指纹、代理版本、分辨率/质量档、帧率/GOP策略和映射版本；现有`scrub-v1`不能冒充新高质量缓存。继续限制内存、磁盘和worker数量，失败不删除原素材；高分辨率缓存的耗时和资源成本实测后确定。

## 验收条件

### 视觉与交互

- 录制器、编辑器和导出入口保持统一控件语言；主按钮不争夺注意力，图标与文本整体居中，正文可读，长工程名不挤压按钮。
- 常驻界面不出现“非破坏性编辑”“精确定位与导出使用原素材”等技术说明；“无声音”、未保存和失败等会改变用户决策的信息保留。
- 100%/125%/150%/200% DPI；真实物理工作区至少覆盖1366×768、1920×1080、2560×1440。在系统可用最小窗口中属性功能仍可到达；无重叠、不可恢复隐藏或错位热区。
- 每类指针分别核对进入、按下、拖出区域、松开、Esc、捕获丢失；裁剪热区在高DPI下保持可用。
- 同一属性通过鼠标、滚轮、键盘、数值框与UIA达到一致结果。验证25%边距、100%阴影、超32px但合法的圆角，避免滑块提前饱和或再次拖动时突跳。
- 中文输入、复制粘贴、Tab、Enter、Esc、空格与剪辑快捷键无冲突；一次拖动一次撤销；选择视频时不显示镜头专属字段。

### 预览清晰度与性能

# Panzo 工作区 UI 重构设计

日期：2026-10-08  
状态：第一版交互设计稿，尚未替换原生应用；未获得用户对本轮视觉的确认。  
范围：应用外壳、图片工作区、录制与视频、素材库、插件管理、设置。  
入口：[可点击原型](prototypes/workspace-v2/index.html) · [原型验证](prototypes/workspace-v2/previews/prototype-tests.json)

## 1. 本次重构要解决的问题

用户提供的主界面截图反映了明确问题：导航与操作按钮等重，连续两排按钮抢占注意力；空图片状态下仍铺满识别参数；没有稳定的字号、边距、颜色与控件体系；图片内容、操作、参数、结果缺少主次。当前源码 `workspace_ui.rs` 直接创建默认 BUTTON / COMBOBOX / EDIT，`workspace.rs` 和 `image_workspace.rs` 以坐标排列这些控件。已有 `editor_ui.rs` 的视频主题没有成为新工作区的共同基础。

本轮先交付可操作的设计稿和实施规格。功能已经整合到同一宿主，但视觉重构不能仅靠修改系统控件颜色完成。真实应用后续按本规格逐页实现、逐页核对截图。浏览器原型的通过不作为原生 EXE 已完成改造的证据。

用户暂未提供本轮风格选择，采用浅色专业工作台作为初稿，同时提供对应深色主题。保留 Windows 原生窗口控制，不使用 macOS 红黄绿按钮；原型顶部的“设计预览”说明只用于评审，不进入正式产品。

## 2. 信息架构与空间分配

左侧固定功能标签：图片工具、录制与视频、素材库。底部固定：插件中心、设置。主页面仍是一个工作空间，点击导航只切换内容可见性。插件中心独立出来，便于用户按需安装功能；低频管理操作放在导航下部。

主区域分为页面标题、区内操作栏、内容画布、上下文属性、底部状态栏。标题区交代当前位置；区内操作栏负责截图/导入/新录制；中间尽量留给图片或视频；右侧只展示当前操作有关的参数和结果。底部显示简短任务状态，详细错误和历史任务通过任务入口查看。

| 区域 | 设计基线 | 窄窗口行为 |
| --- | --- | --- |
| 主导航 | 200 DIP，图标 + 文字，选中项使用柔和强调底色 | 小于约 1100 DIP 时缩为 76 DIP 图标栏，必须保留工具提示和可访问名称 |
| 页面标题 | 74–88 DIP，高度随可用空间调整，标题 21 DIP | 收起搜索框文案，保留搜索按钮和快捷键入口 |
| 操作栏 | 约 56 DIP，主操作使用蓝色，次操作轻底色或无底色 | 先收起次操作文字 / 移入更多菜单，保证截图和导入可达 |
| 图片识别栏 | 约 318 DIP，可按空间缩至 276–300 DIP | 内容独立滚动，不压缩成难读的小字 |
| 设置内容 | 左侧二级导航 + 约 680 DIP 正文 | 二级导航移到顶部，内容单列 |
| 素材与插件 | 网格卡片，列数随宽度调整 | 素材从三列变两列，卡片内文字可换行 |

本轮原型验证范围为 1440×900、1170×820、960×720 CSS 视口。正式应用以 DIP 布局并处理 DPI 变化，需另测 100% / 125% / 150% / 200%，不能用这些浏览器尺寸代替原生多 DPI 通过。暂不扩展到手机布局。

## 3. 统一视觉规范

| 项目 | 规则 |
| --- | --- |
| 风格 | 清晰、克制、以内容为中心；层级来自间距、字重、浅底色与细分隔线 |
| 字体 | Windows 系统无衬线字体，显式中文回退；正文约 14、常规控件约 13、辅助信息 11–12 DIP，页面标题 21–22 DIP |
| 间距 | 以 4 / 8 / 12 / 16 / 24 / 32 为主；同组紧凑，组间留白，标签与输入成组 |
| 控件 | 主操作约 36–40 DIP 高；图标 16–20 DIP，命中区域至少 32 DIP；可访问焦点环独立显示 |
| 圆角 | 输入和按钮 6–8，面板 10–12；不把每行说明都做成卡片 |
| 浅色 | 背景 #F4F6FA，内容 #FFFFFF，正文 #202633，辅助 #626D80，强调 #4263EB |
| 深色 | 背景 #161A22，内容 #202630，正文 #EEF1F7，辅助 #A9B4C8，强调 #708CFF；强调按钮使用深色文字保证对比度 |
| 状态 | hover、按下、键盘焦点、持续选中、禁用、忙碌、错误分别定义；不只依赖颜色表达 |
| 图标 | 一套线性图标，描边与尺寸统一；高频工具保留 tooltip、中文可访问名称和必要快捷键 |
| 动效 | 仅轻量状态过渡；尊重减少动态效果；画布拖动、播放头不添加延迟动画 |

精确颜色和样式初稿位于 `prototypes/workspace-v2/style.css`。生产实现提取语义 token，避免每个窗口各写一套颜色。必须建立 Button、IconButton、Switch、Field、Tabs、Inspector、Status、EmptyState 等共享组件。

## 4. 图片工作区

空状态只突出“从一张图片开始”、区域截图、打开图片和拖入/粘贴提示。右侧用简要说明介绍文字 OCR 和多模态，隐藏无效参数和空白结果框。

截图、导入、素材库打开和视频帧截图均添加为工作区文档。多图片使用文档标签而不是空下拉框；当前会话侧栏提供快速回到素材的入口。画布上方是选择、裁剪、画笔、矩形、箭头、文字、马赛克等工具；导入操作与编辑工具分开，撤销和保存位置固定。

右侧识别面板使用两段切换：文字 OCR / 多模态识图。离线显示语言和本机处理说明；多模态显示提取文字、表格、描述和自由提问。补充提示默认折叠，自由提问时展开。结果直接在原图旁校对和复制，不创建结果窗口。

状态规则：无图片时不显示无效识别操作；任务开始后只锁定冲突操作，显示取消；A 的结果始终归属 A，当前在 B 时不切换、不覆盖 B。手工校对与原图状态跨标签保留。插件处理输出作为新图片加入工作区，自动保存到素材库，原图不变。常规操作使用区内面板，文件选择、桌面选区、明确丢弃修改才使用必要的临时交互。

原型支持真实的本地图片导入、拖放、粘贴以及矩形/画笔标注与撤销。原型的截图、OCR、多模态与滤镜是演示：没有真实屏幕采集或 AI 请求；其余编辑工具展示选择状态和位置，不声称实现完整图片引擎。

## 5. 录制与视频

准备页：左侧选择全屏/窗口/区域，并展示选区概要；右侧同时显示帧率、倒计时、系统声音、麦克风和鼠标跟随缩放。鼠标跟随使用有明确文字的开关，录制前和视频编辑时均可开关。开始按钮只在准备完成时作为主要动作；录制时以停止和时长为主要反馈。

停止后在同一工作区进入视频编辑：画布 → 播放控制 → 时间线，右侧为画面、光标、跟随和声音。时间线区分视频与镜头轨道，不用一个滑杆代替正式剪辑时间线。原型中的简化滑杆仅用于演示播放位置状态保留。

MP4 / GIF 导出在右侧参数面板展开，格式、分辨率、帧率与预计范围按组组织；开始导出后显示进度、取消和输出位置。后台导出不阻止切换到图片区。实际播放、剪辑、音频、鼠标轨迹、硬件编码继续复用现有引擎，不为了视觉改造重写。

## 6. 素材库、插件、设置

素材库：缩略图 + 文件名 + 类型/尺寸/时长 + 时间，提供图片/视频/GIF 筛选和搜索；打开素材进入对应工作区，返回后恢复筛选和滚动位置。多选、删除、排序与长列表虚拟化在生产组件中补齐，不把本轮四个示例卡片当成完整素材库。

插件中心：每项功能显示名称、简述、版本、内置/独立状态及启停开关；管理入口集中更新、回退、卸载。安装前说明作者声明、兼容性、访问范围与完整性结果；原生插件具备用户权限，不能以独立进程误导为沙箱。卸载不会删除用户作品。原型读取本地包清单展示，不执行、安装或声称验证二进制。

设置：外观与行为、识图服务、快捷键、存储与隐私。服务地址、模型、密钥分组；配置保存与测试反馈内联展示，失败不清空输入。正式应用继续使用已实现的本机加密配置。原型只保存浏览器主题偏好，API 字段仅驻留内存，不应填入真实密钥。跨重启恢复全部工作空间是明确的后续功能目标，不作为当前原生能力对外宣称。

## 7. 原生实现顺序与边界

| 批次 | 实现内容 | 主要接入位置 | 退出条件 |
| --- | --- | --- | --- |
| U1 | 共享主题/组件、固定导航、页面标题、状态栏、空状态 | workspace_ui.rs、workspace.rs、editor_ui.rs | 原生真实窗口与设计稿对照，字体/层级/窗口缩放达标 |
| U2 | 文档标签、图片画布工具、OCR/多模态区内面板、任务反馈 | image_workspace.rs、picture_window.rs、workspace_form.rs | 截图→标注→识别→校对→切换全过程保持文档状态 |
| U3 | 录制准备、视频属性、内联导出、统一视觉 | recorder_window.rs、media_settings.rs、preview_window.rs、export_window.rs | 真实录制/播放/导出可用，鼠标跟随开关与原有剪辑行为保留 |
| U4 | 素材库、插件卡片、设置分类、安装确认 | capture_history.rs、plugin_ui.rs、workspace_settings.rs | 实际插件安装/启停/回退、密钥保存、素材检索通过 |
| U5 | DPI、键盘、读屏、性能、实机视觉 | 各页面与 workspace_review.rs | 原生截图和物理输入验证齐全，再替换默认候选 |

现有 Rust 后端、文档 ID、revision、任务取消、素材库、加密设置和插件运行时都保留。UI 读取状态并发送命令，不能再让每个功能自行决定窗口结构。插件贡献能力与操作，宿主负责布局、主题和反馈。

渲染层实现须先完成一条原生垂直切片：新外壳 + 一张真实图片 + 一次真实 OCR。现有 `ADR-0002` 对原生绘制和 WebView2 的比较仍有待验证项；本轮 HTML 是设计载体，不因此直接宣布 WebView2 已接入或迁移选型已通过。无论最终绘制路径，须复用语义 token 和组件契约，禁止退回默认控件堆叠作为视觉交付。

## 8. 原生验收标准

- 与设计稿并排检查五个页面，检查空状态、已加载、执行中、失败、禁用、安装确认和更新状态；不能只给一张理想截图。
- 主操作容易识别；所有文本和菜单在目标尺寸/DPI下可达，无挤压、叠盖、意外滚动条。
- Tab / Shift Tab、Enter、Esc、快捷键与输入焦点一致；图标有可访问名称，焦点与选中状态分离。
- 标签切换只改变可见性，图片标注、OCR 校对、播放位置、参数草稿不丢失；关闭文档才处理丢弃确认。
- 截图/识别/设置结果回到功能区，必要的选区浮层和贴图窗口仍保留；不新增常规业务窗口。
- 多模态 Key 保持加密，任务输入快照和结果归属不改变；插件启停不能绕过权限/生命周期检查。
- 性能验证使用真实媒体与进程指标，不能把原型中模拟任务的响应当成编码、识别性能。

当前通过的是浏览器交互设计验证，详见原型报告；正式原生重构、真实多 DPI、完整读屏与实机性能均待执行。

## 3. 真实播放器基线

脚本：[measure-r0-baseline.ps1](../scripts/measure-r0-baseline.ps1)。在保护副本上运行已有 Release 探针；记录二进制 Hash、素材 Hash和完整 stdout/stderr，测量后再次校验原工程关键资产 Hash 不变。

有效运行：[baseline.json](acceptance/RE-MVP/r0-20260905-122050-4b344774/baseline.json)、[environment.json](acceptance/RE-MVP/r0-20260905-122050-4b344774/environment.json)。

| 素材 | 三次定位到内部播放状态（ms） | 中位数 | 旧 750 ms 门槛 |
|---|---|---:|---|
| F01：约6秒 / 360帧 | 605.297、571.473、618.782 | 605.297 ms | 3/3以内，但没有达到新计划250ms目标 |
| F02：约60秒历史工程 | 2386.286、2309.671、2337.880 | 2337.880 ms | **3/3 Fail** |

另有：两份素材的末尾定位探针均成功；镜头长度更新的 UI 提交耗时分别为 8.324 ms 和 4.722 ms，并通过现有增量路径检查。**提交耗时不是对应视频画面的更新耗时**，不据此认定拖动流畅。

这里的 `Queued playback latency` 在窗口内部定位开始到 `session.play()` 状态完成处采样，不是鼠标/键盘输入到显示器可见首帧。每素材只有3个样本，不能用其分位数替代最终100样本验收。后台 GPU 负载未控制；进程冷启动但操作系统文件缓存未清空。

实测环境：Windows 10 专业版 10.0.19045、i7-14700KF、RTX 4080 SUPER、驱动32.0.16.1062、2560×1440约99Hz，约64GB内存。它不同于计划中的 Windows 11 目标基线；历史文档对机器系统版本的笼统表述不能当作本次事实，也不据此扩大平台支持声明。

### 随机定位进一步检查

对同一 F02 保护副本执行：

```powershell
.\target\release\panzo-cli.exe decode-seek-probe `
  .tmp\r0-20260905-122050-4b344774\F02.panzo\media\screen.mp4 30000
```

本次命令退出码1，报告：`decoder skipped indexed seek target TimeTick(299944240) and returned TimeTick(300009884)`。

这证明该历史媒体的随机定位确实可能跳过索引选择。结合现有精确定位代码的逐级预滚/回退机制，额外解码是长等待的重点排查路径；不能仅通过改变播放按钮文案、延长看门狗或 UI 动效解决。尚未把全部2.34秒按解码/合成/消息调度拆分，R1需补阶段计时再确认占比。

## 4. UI 路径与未完成项

[ADR-0002](ADR-0002-RE-MVP-UI-Candidates.md) 保留两个生产候选：原生 Direct2D/DirectWrite 控件，或 WebView2 UI配合原生预览。HTML原型是本次评审工具，不代表 WebView2 原生嵌入已通过。

R0 剩余工作：

1. 视觉/布局已获用户确认；录制、导出、错误/空状态继续补齐，并在正式窗口另行复验。
2. 同一真实 GPU 预览与时间线的候选实现垂直切片，确认 DPI、焦点、覆盖关系和分发成本。
3. F03帧编号素材、F04真实5分钟工程与F05长工程的统一输入到可见画面采样；当前连续Scrub的RE-PERF-02/03仍为NotRun。
4. 补足更完整的键盘/可访问性、工作区自适应和DPI矩阵；原型两尺寸通过不等于原生窗口通过。

R1 优先处理 F02 长定位与预览任务调度，保留末帧正确性和源资产安全。视觉方向确认不等于原生界面已经落地，也不等于卡顿全部修好。

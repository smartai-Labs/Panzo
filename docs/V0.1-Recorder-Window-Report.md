# Panzo V0.1 Recorder Window 阶段报告

执行日期：2026-09-01（Asia/Shanghai）

## 阶段目标

把已经通过 M1 验收的命令行录制器接入最小应用界面，使用户不再需要预先指定录制秒数。用户点击 Record 开始录制，点击 Stop 或关闭窗口时发出安全停止请求，录制器仍须完成 Capture Stop、输入排空、fMP4 Finalize、Camera Track 生成和 Project Ready。本增量继续接入 Open Last Project 与后台 Export MP4，使录制、重开、预览和交付文件形成应用内闭环。

## 实现范围

- Recorder Window 显示 Primary Monitor、源原生分辨率、目标 60 FPS、录制状态和录制时长。
- UI 只有在第一个有效 WGC Frame 建立 Session Epoch、录制循环真正进入后才切换为 Recording 并开始计时。
- 录制运行在线程中；Stop 使用线程安全且单调的 `RecordingControl`，不强制终止录制线程。
- Finalizing 阶段禁用重复停止，完成后提供 Export MP4、Preview、Project Folder 和 Diagnostics 入口。
- 关闭正在录制的窗口等价于请求 Stop，并等待 Project 完成 Finalize 后再退出。
- 应用启动时扫描 Project Library，只接受媒体存在且 Manifest 状态为 `ready` 或 `recovered` 的 `.panzo` 目录，并自动载入修改时间最新的项目。
- Export 在线程中运行，界面保持响应；输出固定为 1920 × 1080、60 CFR、Hardware H.264，并分配不覆盖现有文件的唯一 `*-1080p60.mp4` 路径。
- Export 继续使用 `ProjectExporter` 的同目录临时文件和原子提交语义；原始 `media/screen.mp4` 不允许作为输出目标。导出失败只影响输出文件，不改变原 Project。
- 导出期间关闭窗口会等待当前 Export 完成后再退出，不强制终止编码线程。
- 默认 Project Library 为 `.tmp/recordings`，每次录制分配不覆盖现有数据的唯一 `.panzo` 目录。
- Backpressure 丢帧与高刷新率源主动限到 60 FPS 分开显示，正常限帧不作为数据完整性错误。

## 自动验收

入口：

```powershell
.\scripts\verify-recorder-ui.ps1 -RecordingMilliseconds 1500
```

验收脚本在独立子进程中启动真实 Recorder Window，设置 45 秒看门狗，自动执行 Record / Stop / Export，随后启动第二个窗口进程复验 Open Last Project：

1. Window Created、Recording Started、Stop Requested、Project Ready 和 Graceful Close 均为 true。
2. Manifest 状态为 `ready`，Capture Content Size 与所选显示器原生尺寸一致。
3. `screen.mp4` 可以通过 Media Foundation 解码，宽高为原生尺寸且 PTS 严格递增。
4. Export MP4 存在，可以解码为 1920 × 1080，PTS 严格递增，且输出不在 Project 媒体路径内。
5. 第二个窗口进程不录制，自动载入同一个最新 Ready Project 并正常关闭。
6. 录制、导出、重开失败或看门狗超时不会被报告为通过。

# 录制与视频代码审查（2026-10-10）

后续修复及回归证据见 [录制与视频可靠性修复](Recording-Video-Fixes-2026-10-10.md)。下文保留修复前的审查记录。

## 范围与验证边界

本次仅进行源码和调用链审查，未修改生产源码、启动录制、改动用户工程或执行导出。以下“确认”指可以从当前源码确定的逻辑缺陷；用户设备上的实际耗时、触发频率和显存占用尚未做运行采样。此前已报告的预览窗口隐藏、视频属性面板分叉、视频选择被清除、重复播放指针、字幕草稿提交等问题不重复计入。

共因是新自由片段模型（visual_clips、多轨道、项目总时长）已经接入部分预览和导出，但字幕、跟随创建、音频来源选择及异步任务管理仍有旧模型路径。

## 新发现

### A01 / P1：同一素材不同时间点的预览缓存互相覆盖，可能形成暂停后的持续重绘

- 位置：`crates/panzo-windows/src/platform/timeline_visual.rs:230`，`preview_window.rs:1211`、`:5712`。
- 条件：同一个视频或 GIF 被放入两条同时可见的轨道，片段入点或起点不同。
- 原因：请求包含 path + tick，但 pending / ready 都只按 path 保存一个结果。交互模式在目标帧未完成时直接返回该路径上一次的帧。每次解码完成又向主窗口发送重绘消息。
- 可推导序列：A 时间帧完成 → B 请求并暂用 A 帧 → B 完成触发重绘 → A 请求并暂用 B 帧 → 重复。暂停时两个时间点也不能同时稳定命中缓存。
- 影响：两个图层可能显示错误时间帧，暂停后仍持续解码、重绘；交互预览与等待精确帧的导出路径可能不一致。
- 验证要求：同素材两层分别取 1 秒、5 秒，暂停后像素各自稳定，解码请求和重绘计数停止增长。

### A02 / P1：多层合成主动使字幕和 GPU 输入缓存失效

- 位置：`crates/panzo-windows/src/platform/compositor.rs:688`、`:711`、`:776`、`:871`。
- 原因：每帧先画基础层、素材层，再画标注层。前面的层以 annotations=false 调用 render_layer，于是 active/subtitles 为空，直接清空 annotation_cache 和 annotation_raster；最后的标注层只能重新生成字幕图像。source_cache 同时只有一个槽位，源视频、素材视频、最终叠加层轮流替换输入纹理。
- 影响：即使字幕文字和样式未变化，也反复光栅化字幕、创建/上传纹理。较高分辨率和多个图层会放大开销；确切耗时需采样。
- 验证要求：固定字幕、多层视频连续播放时，字幕光栅化次数随字幕内容变化，而不是随帧数增长；暂停重绘复用各层纹理。

### A03 / P1：AI 字幕没有使用真正的时间轴混音和总时长

- 位置：`crates/panzo-windows/src/platform/media_jobs.rs:180`、`:191`、`:275`；对照 `crates/panzo-core/src/timeline.rs:141` 和 `crates/panzo-windows/src/platform/export.rs:346`。
- 原因：识别使用 settings.audio_clips 而不是 mixing_clips()，遗漏 visual_clips 所带音频和新的轨道静音处理；识别时长仍取 video.duration()。原声音轨映射也仍按旧 VideoEdit。
- 条件：导入带声音的新视频、移动原视频、延长旁白/音乐、静音自定义音轨后执行识别。
- 影响：导出或播放能听到的声音未必被识别；后半段漏字幕；识别内容和时间位置可能与当前时间轴不一致。
- 验证要求：原视频 1 分钟、旁白 3 分钟，识别覆盖相应项目范围；导入视频音频可识别；静音轨道不进入“当前混音”；移位后字幕对齐。

### A04 / P1：新增字幕和跟随片段仍被旧源视频范围限制

- 位置：`crates/panzo-windows/src/platform/media_panel.rs:1052`、`preview_window.rs:3977`、`media_timeline.rs:1108`。
- 原因：新字幕结束时间裁到 s.edit.duration()；跟随创建先调用旧 VideoEdit.clip_at(project_tick)，找不到即直接返回。
- 条件：源视频 1 分钟，但素材把工程延长到 3 分钟，播放头在第 2 分钟；或者原视频被移动至旧范围之外。
- 影响：字幕添加报“移到视频范围内”；“在播放头添加跟随片段”可能没有任何效果。
- 验证要求：创建动作使用项目时间和目标轨道，不能因为旧源视频不存在就静默忽略。

### A05 / P1：静音时首次移动原视频，会把片段音量永久写为零

- 位置：`crates/panzo-windows/src/platform/media_timeline.rs:689`、`:701`、`:180`。
- 原因：旧视频转换为 visual_clips 时，source_muted=true 会写入 clip.gain=0；后续解除轨道静音只修改 track.muted，不恢复这个 gain。
- 条件：静音原视频 → 首次拖动视频片段 → 解除轨道静音。
- 影响：图标已解除静音，但预览和导出仍然没有该片段声音；需要另改片段音量才能恢复。
- 验证要求：静音与片段音量独立保存，模型转换不改变原有音量。

### A06 / P1：工程切换缺少旁白、AI 和项目素材导入的收尾协调

- 位置：`crates/panzo-windows/src/platform/editor_navigation.rs:181`、`:216`；`media_panel.rs:247`、`:1127`；`project_bin.rs:24`；`project_assets.rs:30`。
- 原因：导航只等待保存、导出、背景任务。active_task() 用于任务展示、停止入口和素材删除限制，没有接入离开工程的判断。项目素材导入任务随素材面板销毁而取消。旁白/AI 完成时 snapshot(s) 若发现工程已切换，会拒绝提交。
- 影响：录音或导入可能未进入素材库；旁白文件虽已生成在旧工程目录，却没有对应素材记录。不能据此说磁盘原文件被删除，但结果对用户不可见。
- 验证要求：任务运行时打开另一工程、开始新录制、退出，均有明确的等待/停止/取消与结果归属流程。

### A07 / P1：AI 结果的过期检查遗漏新片段和轨道状态

- 位置：`crates/panzo-windows/src/platform/media_panel.rs:1132`。
- 原因：任务完成时只比较 video、subtitles、audio_clips 和 audio，未比较 visual_clips、tracks、clip_tracks 等影响时间映射和混音的数据。
- 条件：AI 处理中拖动、裁剪或变速新视频片段，或者修改音轨静音/归属。
- 影响：旧编辑状态生成的字幕仍可能被接受，提示成功但字幕与新时间轴不匹配。
- 验证要求：识别任务绑定完整输入快照或相关版本；时间映射/混音变化后不得自动覆盖当前字幕。

### A08 / P2：字幕字号选项与校验规则冲突，并静默失败

- 位置：`crates/panzo-windows/src/platform/media_panel.rs:143`、`:886`；`crates/panzo-core/src/media_edit.rs:179`。
- 原因：界面列出 8、10、12、16 等像素字号，底层限制 font_size 为画面高度的 1.5%～12%。live_subtitle_style 遇到无效样式直接 Ok(())。
- 影响：1080 高度下最小值为 16.2 px，8～16 均不生效；2160 高度下最小值为 32.4 px。用户看见选项变化，却看不到画面变化，也没有错误说明。
- 验证要求：字号单位和范围统一；下拉框提供的值都能使用；自定义值无效时明确反馈。

### A09 / P2：新素材解码未接入导出取消信号

- 位置：`crates/panzo-windows/src/platform/export.rs:379`；`compositor.rs:418`；`timeline_visual.rs:178`、`:258`。
- 原因：导出在帧循环检查自身 cancel，但 Visuals 使用独立取消标记；非交互取帧使用阻塞 recv()。独立标记直到 Visuals 析构才设置。
- 条件：导出正在为新素材扫描索引、定位或解码时点击取消。
- 影响：取消不能中止正在进行的新素材解码，需要等该阶段返回；长素材或慢解码时退出明显延迟。没有足够证据断言必然永久死锁。
- 验证要求：统一取消令牌，等待可中断，取消后不继续建立长视频索引。

### A10 / P2：新视频片段的时间轴缩略图退化成重复封面

- 位置：`crates/panzo-windows/src/platform/media_timeline.rs:378`；`project_bin.rs:747`。
- 原因：新片段直接重复绘制素材卡片的同一张封面，没有传递片段时间和源入点；旧视频使用另一套按时间抽帧的路径。
- 影响：移动原视频完成模型转换后，缩略图行为改变；裁剪、变速后缩略图不反映画面内容，误导剪辑。
- 验证要求：旧、新视频统一按项目时间映射源时间抽帧。

### A11 / P2：素材解码器缓存超过四个文件时会反复重开并重扫索引

- 位置：`crates/panzo-windows/src/platform/timeline_visual.rs:91`、`:186`。
- 原因：只保留四个 Source，满后直接 pop_front，命中不更新使用顺序；每次重新打开视频都完整 native_index。
- 条件：多个素材交替出现，尤其同时可见五个不同视频。
- 影响：解码器和索引可能在每轮帧处理反复创建，暂停/播放/导出均有明显放大开销的条件。
- 验证要求：索引可复用、缓存按实际使用管理；同屏多个素材不应逐帧扫描文件。

### A12 / P2：视频导入失败或取消后，已经生成的工程内文件可能没有回滚

- 位置：`crates/panzo-windows/src/platform/project_assets.rs:180`、`:189`、`:193`、`:199`。
- 原因：视频音频先解码成工程内 PCM，随后才检查取消和复制视频；后续失败时没有一起删除成功生成的 PCM。SRT/媒体复制完成后也没有统一“提交素材记录失败”清理事务。
- 影响：工程目录留下没有素材记录引用的文件，多次失败可持续占用磁盘；这是工程内残留，不是用户原文件被误删。
- 验证要求：导入输出先暂存，素材记录提交成功后统一完成；失败清理仅限该任务创建的文件。

## 已排除或尚不能确认

- 跟随片段删除残留：上层 ProjectEditorSession::delete_segment 会同步清理 follow_positions 和 clip_tracks；删除轨道也有 camera_ids 清理，未列为缺陷。
- 工程总时长：project_duration() 和导出默认范围已经纳入放置的视频、音频、字幕；问题主要在字幕/跟随/识别等消费者还使用旧时长，不能说全部时长实现都错。
- 解码线程 COM 初始化：MfBgraDecoder 与 AudioDecoder 内部初始化，不能因外层 worker 未显式初始化就判断错误。
- 保存/恢复：快照包含 WorkbenchSettings 新字段，本轮没有确认普遍性的保存字段丢失。
- 屏幕录制主循环：启动在后台、停止请求、暂停时间映射和结束收尾均有相应路径。本轮没有证明其普遍性失效；设备断连、窗口尺寸变化、暂停恢复仍需独立实机用例。
- 所有按钮都需点击两次：没有确认一个覆盖所有按钮的统一原因；已确认静默参数拒绝、旧时长创建失败、选中状态丢失等会造成不同形式的“不生效”。

## 建议修复顺序及验收

1. 优先修复已发现的黑屏/选择状态，以及 A01/A02 预览循环与缓存失效。
2. 统一项目时间、片段类型、混音输入、静音和参数校验，处理 A03/A04/A05/A07/A08。
3. 统一异步任务归属、退出、取消及导入事务，处理 A06/A09/A12。
4. 统一缩略图和素材索引缓存，处理 A10/A11。
5. 连续操作验收至少覆盖：同素材重叠、静音后移动再解除、1 分钟视频加 3 分钟旁白、AI 运行中编辑、录音中切工程、导出解码中取消，以及 1080/2160 尺寸下的小字号。

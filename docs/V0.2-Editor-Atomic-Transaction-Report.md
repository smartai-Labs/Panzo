# Panzo Editor 崩溃安全保存事务报告

执行日期：2026-09-02（Asia/Shanghai）

## 阶段结论

`ED-ATOMIC-001` 已完成。Editor 不再依次替换 Camera、Workbench 后追加 History，也不再依靠失败后的“尽力回写”避免版本混合。当前保存采用写前多文件事务，以单一原子事务标记作为提交点；应用异常退出后，Project 只会恢复为完整旧 Revision 或完整新 Revision。

## 事务协议

1. 验证 Camera Track、Workbench Settings、History 最后 Revision 与 Camera Hash。
2. 在 `edit/.transactions/<uuid>/` 写入完整的新 Camera、Workbench、History 和可选的首次 Auto Draft。
3. 对每个暂存文件执行 `sync_all`。
4. 原子发布 `edit/save.transaction.json`。这是唯一逻辑提交点。
5. 将暂存内容幂等物化到规范固定路径；Auto Draft 使用禁止覆盖的原子创建。
6. 全部文件完成后删除事务标记，再清理暂存目录。

提交标记发布前崩溃时，打开 Project 会清理未提交暂存并继续使用完整旧版本。提交标记发布后崩溃时，打开 Project 会校验暂存 Hash、Schema、Camera、Settings 与 History Revision，然后完成前滚。标记在物化期间始终存在，因此任何新读取入口都会先恢复，不会把部分固定路径误认为有效版本。

`ProjectEditorSession::open`、共享 `load_effective_edit_state` 和 Camera Regenerate 都已接入恢复入口。源视频、Cursor 和 Clicks 不属于事务写集合。

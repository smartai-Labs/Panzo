# 编辑体验优化 — 2026-09-19

候选：`dist/Panzo-RE-MVP-workflow-20260919/panzo.exe`。本轮完成用户确认的六项优化，原先的三区卡片、深浅主题、标题栏按钮和低清时间线缩略图保留。

## 属性面板与裁剪

- 属性面板只裁掉屏幕外的命中区域，露出的部分仍可点击；开始精确输入前会自动把完整数值框滚入可见范围。滑块计算使用原始控件几何，避免在面板边缘跳值。
- 播放速度、画面裁剪分组可折叠，恢复、裁剪和锁定操作保留在标题右侧。沿用图标、悬浮提示和悬浮边框样式。
- 点击裁剪图标进入完整源画面的辅助视图，八个手柄调整边角，框内拖动移动保留区域，框外暗化。比例锁同时约束拖动、滑块和数值修改；比例预设重新定义保留区域。
- 拖动只更新选区覆盖层，复用已解码画面。一次手势一次撤销，Esc 取消正在进行的手势，Enter 或再次点击裁剪图标完成。播放、定位、选择其他对象、分割及删除会结束辅助视图；清除在途旧请求，避免之后闪回完整源画面。
- 辅助线只属于编辑器，不进入导出；镜头、光标与正式预览继续使用统一裁剪坐标。

已检查深浅主题及 96 / 144 / 192 DPI 的界面绘制，例如[深色裁剪](acceptance/workflow-20260919/workflow-crop-Dark-96.png)、[高 DPI 浅色裁剪](acceptance/workflow-20260919/workflow-crop-Light-144.png)。原生事件测试覆盖拖动、取消、撤销重做、比例锁联动及退出裁剪后的预览状态。

## 画布与时间线

“画布”页增加原始、16:9、9:16、1:1 和宽高输入。宽高为 64–8192 的偶数，总像素不超过 33,554,432；非法输入保留供修正，不提交部分修改。预览重新创建匹配尺寸的呈现表面，撤销和重开恢复对应尺寸。

导出默认采用画布尺寸，1080p 选项按方向等比限制为横向 1920×1080、竖向 1080×1920、方形 1080×1080。沿用不额外放大裁后源像素的规则，所以大画布中可能保留背景；这不是拉伸填满。[竖向画布](acceptance/workflow-20260919/workflow-portrait.png)、[自定义画布](acceptance/workflow-20260919/workflow-custom-canvas.png)。

播放按钮两侧增加逐帧图标。时间线 ← / → 按 60 fps 输出帧定位，Ctrl+方向键跳片段边界，Shift+方向键保留 5 秒跳转；聚焦参数控件时方向键优先调整该控件。视频修剪和镜头移动 / 修剪吸附时显示黄色虚线，Alt 临时解除吸附。

## 布局和恢复

属性栏宽度、显隐、时间线高度与两个视频分组的折叠状态写入应用偏好，下次打开恢复并受当前窗口空间约束。切换主题不会丢失布局。

普通编辑窗口每约 2 秒检查变更，在手势结束、保存及背景导入任务空闲后，由后台线程原子写入独立恢复文件。重开工程会载入最近成功写入的副本并提示，整次恢复可撤销。显式保存继续沿用已有事务；正常选择“不保存”关闭会先禁用在途写入，再清除副本，防止后台线程把已丢弃内容重新写回。

副本校验工程身份、源时长、保存基线、内容 Hash 和编辑有效性；过期或损坏副本保留为独立文件，打开上次保存的工程。最后一次尚未写完的修改不保证恢复，手动保存仍是确定的保存操作。原视频、事件及已保存编辑不由恢复操作覆盖。

编辑格式升为 schema 5，新增可选画布尺寸；兼容读取 schema 1–4，旧文件默认源尺寸。常规测试覆盖旧文件迁移、非法尺寸的原子拒绝、保存重开、恢复撤销和源资产 Hash 不变。

## 拖动性能对照

发现向前定位也复制了目标前 100 ms 内的原分辨率 BGRA 帧。现在向前跳过这些复制，反向只保留 50 ms；保留原生分辨率、字节预算和松手后的原素材精确定位。时间线缩略图仍为 160 像素低清缓存。

同机、同一份已准备缓存的 2560×1440 混合变速 / 裁剪工程，每次 12 秒；[完整对照数据](acceptance/workflow-20260919/scrub-comparison.json)：

| 构建 / 次数 | 请求到 Present P95 | 最长画面更新间隔 | 拖动呈现帧数 |
|---|---:|---:|---:|
| 上一版 1 | 105.097 ms | 131.412 ms | 349 |
| 上一版 2 | 105.481 ms | 129.671 ms | 350 |
| 本版 1 | 15.341 ms | 232.165 ms | 387 |
| 本版 2 | 19.393 ms | 207.238 ms | 398 |

四次均零媒体错误、零降清帧、释放后精确定位且随后播放完成。P95 显著降低，但本版最长更新间隔与 P99 比本次基线更高（P99 为 172–191 ms，基线约 129–131 ms），仍有长尾回归需要继续处理，不能称为全面性能改善。每轮均记录一次 OS 输入中断，不能据此宣布全部性能验收通过。中间方案及格式统一前的构建记录也保留，未使用最好的一次替换最终打包构建成绩。冷缓存、真实长素材及完整物理输入矩阵仍待完成。

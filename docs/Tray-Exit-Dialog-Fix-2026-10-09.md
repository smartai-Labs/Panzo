# 托盘退出重复确认修复 · v8

启动：`target/desktop-v8/release/panzo.exe`。

## 原因与复现

托盘退出将 `close_when_finished` 置为 true，录制窗口的定时器会持续投递 `WM_QUIT_WINDOW`。旧流程处理退出消息时，向每个图片窗口同步发送 `WM_CLOSE`，未保存图片随后打开 `MessageBoxW`。确认框自己的消息循环继续分发定时器及退出消息，而退出标记仍未消费，也没有重入保护，于是同一张图片反复进入关闭确认。

使用两个合成图片的独立测试进程，只触发一次托盘退出路径，v7 即出现四个同时打开的“关闭图片”确认框；测试随即结束该测试进程，避免继续叠加。没有操作用户原先运行的实例。

## 修复

- 对投递中的退出请求去重。在进入退出确认前消费 `close_when_finished`，等待选择时定时器不再自动发起下一次退出。
- 使用线程内的确认流程锁，阻止嵌套退出确认和单张图片关闭确认。锁随当前流程返回释放，取消后可以正常再次操作。
- 多张未保存图片合并为一次退出确认：全部快速保存到截图历史、放弃这些未保存修改并退出、取消退出。
- 准备退出阶段不销毁任何图片。只有所有必要保存成功且用户允许退出后，才随主窗口一并关闭；保存失败中止退出，保留所有图片。
- 单张图片关闭仍有自己的保存确认，同样受重入保护；无法取得有效选择时按取消处理。

## 同轮发现的绘图退出异常

检查测试进程的 Windows 崩溃记录发现，缓冲绘图的 `PaintRuntime` 在线程局部变量析构阶段调用 `BufferedPaintUnInit`，发生 `GDI32.dll` 访问异常；有的实例即使返回退出码 0 仍生成了异常转储。测试转储的地址与符号记录见 `dump-diagnostics.json`。

改为由窗口消息循环显式持有 `PaintSession`，在循环返回时释放。嵌套绘制按引用次数管理，独立控件的绘制也在结束缓冲帧后释放，不再在线程退出的 TLS 析构器中调用绘图 API。新增测试覆盖嵌套会话、不同释放顺序及释放后的重新初始化。

## 验证记录

测试脚本：`scripts/test-exit-release.py`。使用隔离的用户目录和合成 PNG，测试只枚举、操作及结束自己创建的进程。

- v7 对照：单次托盘退出复现叠加弹窗。
- v8：等待确认时注入 80 轮应用退出、主窗口关闭、单张图片关闭消息，只允许一个确认框。
- 取消：全部图片保留，等待后没有自动再次弹窗。
- 放弃：正常退出，不生成新截图，不修改源文件。
- 全部保存：生成两张修改后的截图，尺寸匹配旋转结果，随后正常退出。
- 保存失败：用测试目录中的同名文件模拟无法创建输出文件夹；在主界面显示错误，不增加确认弹窗；保留所有图片，恢复目录后可重试成功。
- 无未保存图片：直接退出。
- 同时检查所有测试进程退出后是否产生新的崩溃转储，避免仅凭退出码漏报绘图清理异常。

证据目录：`docs/acceptance/exit-dialogs-v8-20261009/`。构建指纹：`target/desktop-v8/release/candidate-build.json`。

## 最终结果

- `panzo-windows` 单元测试：216 通过、0 失败、37 个需专门环境的测试忽略；两个新增测试均通过。
- 退出专项原生测试通过，覆盖 4 个独立进程，未生成新的崩溃转储。
- 主界面原生回归通过：顶部导航、目录编辑、设置草稿及弹窗复用、素材预览、图片裁剪、主题切换和撤销范围；该进程也未生成新的崩溃转储。
- 目录回归脚本原先只等待输入框隐藏，而赋值发生在隐藏之后；已改为同时等待路径提交完成，消除测试时序竞争。
- 早先一次独立测试被第三方豆包输入法 `tsf-oime-core.dll` 异常中断；未修改输入法设置。最终退出专项及界面回归均完整通过，此第三方异常不作为已修复事项。
- 发布目录的二进制哈希、构建来源与当前源码再次核对一致，完整记录见 `verification-summary.json`。

## 1. 本轮决定

采用紧凑的桌面编辑器布局。窗口的主要任务是编辑图片和视频，组织方式以菜单、工具、文档和属性为基础。

- 工作区移到顶部：图片工具、录制与视频、素材库；插件与设置放在右侧。
- 固定菜单栏、操作工具栏、文档标签，取消 v2 的宽导航、大标题和欢迎卡片。
- 图片工具在左侧单列排列，中央给画布，右侧是可收起的识别 / 图像信息面板。
- 当前会话素材放在底部缩略图条。它和文档标签共同指向同一文档，不复制文档状态。
- 深色石墨灰为默认主题，浅色沿用同一布局；浅灰绿仅用于激活、选择和主动作。
- 素材库采用文件浏览器式结构；插件采用带版本与状态的列表；设置采用偏好分类和紧凑分组。
- 标题栏（软件名称、最小化 / 最大化 / 关闭）与主体外壳使用相同背景色：深色 #303235、浅色 #E7E9E5。切换主题时同步背景与文字颜色，保留 Windows 原生窗口按钮、拖动、双击最大化和窗口吸附。

浏览器仅承载交互设计稿，不能据此推导生产应用将改用网页技术。独立预览窗口隐藏地址栏，便于评审桌面空间比例。

原型在 1440×900、1170×820、960×720 的视口进行检查。960 宽仍保留顶部主要工作区文字。真实原生 100% / 125% / 150% / 200% DPI、系统文本缩放和高对比度需要另行验证。

## 3. 图片工作区

打开时可为空白工作区，中心只显示打开 / 截图和拖放提示，右侧面板不占空间。交互稿默认加载两张示例文档，便于直接评审；加上 ?empty=1 可查看空状态。

截图、导入、粘贴、素材库打开和视频帧截图进入同一文档模型。文档标签和底部缩略图指向相同 ID。工具栏不随着 OCR 模式切换重新排序。未保存状态显示在标签和画布状态行中。

右侧分为「文字识别」「图像信息」两个页签。「文字识别」内切换文字 OCR / 多模态；参数、识别动作、可编辑结果由上到下排列。多模态提供文字、表格、画面描述和自由提问，补充要求可展开。服务配置仍在设置区。

识别任务绑定源文档。识别期间切换图片或工作区，不跳回源文档，也不把结果写到另一张图上。校对内容、语言、问题和结果保留。面板收起后任务继续，展开恢复原状态。关闭有标注的文档才弹出丢弃确认。

拼图、批处理、图像插件使用相同右侧上下文面板。主业务流程保持在工作区内，文件选择、必要确认、截图选区浮层和贴图窗口仍按其用途独立存在。

示例中的标尺、颜色样块属于视觉示意。生产实现需绑定实际画布变换、标注颜色和文档尺寸，不能复制固定刻度当成完整能力。

## 4. 录制与视频

录制准备由中央来源预览和右侧录制参数组成。来源可切换全屏 / 窗口 / 区域。右侧提供帧率、倒计时、系统声音、麦克风、鼠标跟随缩放，底部固定录制动作。

停止后直接进入视频工程。同样使用顶部工具栏、中央画面、底部时间线和右侧属性。鼠标跟随缩放可在录制前和编辑时开启 / 关闭。

导出替换右侧面板，提供 MP4 / GIF、帧率和尺寸；不再开常规业务窗口。后台任务保留来源和导出参数快照。提取当前帧进入图片工作区后，视频播放位置与编辑状态保留。

原型只演示状态变化；真实采集、鼠标记录、编码、声音和剪辑继续由既有 Rust 能力完成。

## 5. 素材、插件与偏好

素材库：左侧文件分类，中间缩略图，顶部路径和搜索。保留名称、尺寸、类型与时间，点击图片 / 工程进入对应工作区。生产版本需补足排序、多选、长列表虚拟化和滚动位置恢复。

插件：列表显示名称、说明、版本 / 来源、启用状态和管理入口。安装本地 .panzoplugin 仍由文件选择与来源确认完成。停用阻止新任务，已启动任务按生命周期规则处理；卸载保留用户素材。原生插件的权限和完整性检查不因 UI 重构改变。

设置：外观与行为、识图服务、快捷键、存储与隐私。配置分组排列，保存与连接结果最终应在设置区内反馈。正式应用继续使用已实现的加密配置；原型的 API 输入只驻留内存，不保存也不发起请求。跨重启恢复工作区仍是后续实现目标，不能把设置样式当成现有能力。

## 6. 原生改造顺序

| 批次 | 主要接入位置 | 交付条件 |
| --- | --- | --- |
| U1 外壳与共享组件 | workspace_ui.rs、workspace.rs、editor_ui.rs | 顶部工作区、菜单、紧凑工具栏、主题、状态栏；真实窗口与设计稿对照 |
| U2 图片垂直切片 | image_workspace.rs、picture_window.rs、workspace_form.rs | 真实截图 → 标注 → OCR → 校对 → 切换保留状态；可收起属性面板 |
| U3 录制与编辑 | recorder_window.rs、media_settings.rs、preview_window.rs、export_window.rs | 真实采集 / 播放 / 导出，跟随开关与帧率行为不回退 |
| U4 资源与管理 | capture_history.rs、plugin_ui.rs、workspace_settings.rs | 真素材、插件启停 / 安装 / 回退、密钥保存接入新组件 |
| U5 实机验收 | 各页面、workspace_review.rs | 多 DPI、键盘 / 读屏、真实媒体性能、实机截图后才替换默认候选 |

保留现有 Rust 后端、任务 ID / revision / 取消、文档状态、素材库、加密配置与插件运行时。UI 读取状态、发出命令，插件贡献能力，宿主统一布局与反馈。渲染选型仍需以实际垂直切片验证，不能用原型截图证明原生迁移完成。

## 7. 本轮验证与限制

运行：node scripts/test-desktop-v3-prototype.cjs。

脚本启动专用临时配置的无头 Chromium，不连接现有用户浏览器。检查空状态、画布标注 / 撤销、后台结果归属、停用插件、内联处理与取消、录制 / 跟随 / GIF 导出流程、素材筛选与服务字段、命令与主题、小窗口布局、面板收起 / 恢复和素材切换。

截图和结构检查用于证明设计稿可操作，不代表原生 EXE、完整无障碍或真实媒体任务通过。详细结果以当前 [验证 JSON](prototypes/desktop-v3/previews/prototype-tests.json) 为准。

v2 作为被否决方案归档：[原规格](UI-Workspace-v2-Rejected-2026-10-08.md)。后续实现以本文件 v3 为设计基线。

## 8. 标题栏同色补充

用户要求标题栏与主体背景一致。对应范围是软件名称和窗口控制按钮所在的系统标题栏，不是图片画布。顶部功能区也改为同一外壳底色，避免标题栏与内容之间出现独立色带。

原型已同步 `theme-color` / `color-scheme` 提示，并统一 `--chrome-top` 与 `--chrome`。普通浏览器窗口或 `--app` 文件预览是否采用该提示由浏览器决定，浏览器内容截图不包含系统标题栏，不能据此声称标题栏视觉验收通过。

原生代码已有 `editor_ui::apply_window_chrome` 与 `DWMWA_CAPTION_COLOR`。接入 v3 时将标题栏背景绑定外壳颜色，标题文字绑定当前主题文字色；创建窗口、切换主题后同步更新。不得只改旧标题栏颜色而保留未迁移的旧主体配色。按钮悬停 / 关闭警示与系统高对比度行为仍按平台规范处理。

实现依据：[Windows 标题栏颜色属性](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)、[Edge 应用主题颜色](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/how-to/icon-theme-color)。本轮仅更新 v3 设计稿，未更换原生 EXE。
